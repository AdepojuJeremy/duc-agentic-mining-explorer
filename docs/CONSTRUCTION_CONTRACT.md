# Locked construction contract

The construction contract is the boundary between **route validation** and **vignette writing**.

The explorer proposes a candidate route and exact source spans. The independent validator decides whether the route is valid and, if promoted, normalizes the formal labels and specifies the decision components Stage 2 is allowed to affect. The host then creates `construction_contracts.yaml` before the generator is called.

A contract locks:

- candidate identifier;
- decision domain;
- fixed clinical question;
- baseline and modifier source identifiers;
- exact Stage-1 and Stage-2 evidence spans;
- evidence taxonomy;
- warranted update class;
- affected decision components;
- allowed constructed scenario premises;
- source provenance, authority tier, status/currentness, and seed-corpus metadata.

The generator produces only variable vignette content. Immutable identifiers, domain labels, taxonomy labels, source identifiers, provenance, and affected-component fields are copied into the final proposal by the host application rather than regenerated by the model.

This prevents the vignette writer from silently changing the route after validation and avoids failures caused by asking an LLM to reproduce immutable metadata exactly.
